# Change report: shopware-playwright-suite

**Date:** 2026-09-25
**Scope:** fixing the smoke suite for the **Echonut** (live shop) and **Würth** (staging mirror) profiles without breaking the **demo** profile.
**Status:** nothing is committed. All changes are in the working tree (`git diff`).

## Result

| Profile | Before | After |
|---|---|---|
| Echonut | 22 failed / 22 passed | 41 passed, 3 failed (all 3 are real site bugs, see `echonut-bugs.md`) |
| Würth | 23 failed / 17 passed | all passing except the 2 known site issues, which now show as "expected to fail". Registration check fixed: the account under-review page is expected. |
| Demo | — | unchanged (same pre-existing delivery-info failure as on the original code) |

**Design rule used throughout:** shop-specific fixes go into `projects/<shop>.ts`. Shared code only got changes that are *optional* (only active when a profile sets the new option) or *defensive* (only kick in when the site actually has that element). None of the new flags is set in `demo.ts`, and Echonut sets only the ones it needs.

## 2. Config and selectors (`src/config/`, `src/selectors/`)

### `src/config/types.ts`
New fields. All are optional except `orderPlacement`:
| Field | Purpose |
|---|---|
| `features.orderPlacement` | `false` → checkout tests verify up to the payment step and pass with an "order not placed" note |
| `features.guestPrices?` | `false` → skip price, tax, delivery and total assertions for guests (B2B shops) |
| `routes.registerPending?` | registration ends on an "under review" page instead of `/account` |
| `CustomerAddress.phoneNumber?` | sent to the Store API and filled in the register form |
| `customer.extraFields?` (`ExtraFormField`) | extra registration fields filled in order; `{random}` = 9 random digits |
| `knownIssues?` (`KnownIssue`) | tests failing because of a confirmed shop bug are marked "expected to fail" |

### `src/selectors/shopware67.ts`
New default keys. Each one matches nothing when the element isn't there, so there's no effect on other shops:
- `product.wishlistConsentAccept`: accept button of the wishlist-cookie off-canvas
- `register.reveal`: "New customer" tab that hides the form (Echonut checkout)
- `register.emailConfirmation`, `register.passwordConfirmation`: Shopware's "require confirmation" setting
- `register.guestToggle`: `#continueAsGuest` checkbox (inverse of `createCustomerAccount`)
- `register.phone`: `billingAddress[phoneNumber]`
- `checkout.paymentButtons`: PayPal smart-button container

## 3. Page objects and components (`src/`)

| File | Change |
|---|---|
| `src/components/Header.ts` | All header getters target the **visible** copy. Themes render the desktop and mobile header twice, which caused the strict-mode errors and mobile search failures. `cartTotal()` takes the last number in the text, because Echonut only has the total in an aria label. |
| `src/pages/AuthPage.ts` | New `openRegistration()`, which uses `routes.register`: Echonut only shows the register form there. New `revealRegistration()`, which clicks the "New customer" tab if the form is hidden. `fillRegistration()` fills `extraFields`, the e-mail and password confirmation fields, and the phone number when they exist. It picks zipcode and city from dropdowns when they are dropdowns, handles the guest checkbox, and skips disabled dropdowns. New helper `setField()`. |
| `src/pages/ProductPage.ts` | New `addToWishlist()`, which accepts the wishlist-cookie consent if it appears and clicks again. New `productNumberValue()`, which strips labels like "Art.-Nr.". `switchVariant()` works when the theme leaves off the `is-combinable` class. |
| `src/pages/CartPage.ts` | `setQuantity()` supports a quantity `<select>` (Echonut). |
| `src/pages/CheckoutPage.ts` | `expectOnConfirm()` checks the confirm form. It requires the submit button only when `orderPlacement` is true. New `expectPaymentReady()`: one payment method is selected, and either the submit button or the PayPal buttons are present. |
| `src/pages/ContactPage.ts` | Fills only **visible** fields. Würth has a hidden, preset `lastName`. |
| `src/api/StoreApiClient.ts` | Sends `billingAddress.phoneNumber` when it's configured. |
| `src/fixtures/index.ts` | New auto fixture `knownIssue`, which marks matching tests as expected to fail. The customer fixture's UI fallback uses `openRegistration()`. |
